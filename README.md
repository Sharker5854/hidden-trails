# hidden-trails
Social platform for travelers for the preservation of local and regional monuments.


<h2>При первом запуске проекта</h2>
<b>Прежде чем делать "docker compose up --build" нужно создать первую миграцию, чтобы при первом запуске приложения пустая БД заполнилась таблицами, описанными в моделях ORM.</b>
Находясь в директории services/users нужно выполнить: <i>poetry run alembic revision --autogenerate</i>
В директории alembic/versions создастся первый файл миграции, который при первом запуске контейнера приложения подхватится и применится к БД, создав таблицы описаные в models/


<h2>Как вносить изменения в модели</h2>
Вот я что-то изменил в файлах из папки models..
Далее, <b>не останавливая контейнер postgres (чтобы локальный alembic с моего компа мог достучаться до postgres через прокинутый на хост порт 5432)</b>, мне нужно выполнить команду: <i>poetry run alembic revision --autogenerate</i>
Создастся новый файл миграции. Далее, перезапускаем контейнеры приложения и postgres командами:
<i>docker compose down</i>
<i>docker compose up --build</i>
После этого, при запуске контейнера с приложением, команда зашитая в CMD в Dockerfile применит миграцию изнутри контейнера в БД и схема таблиц корректно обновится.
<i>P.S. Важный нюанс: выполнить команду "poetry run alembic revision --autogenerate" можно локально без проблем, только потому, что в alembic.ini захардкожена ссылка на подключение к БД с хостом 'localhost'. Но изнутри контейнера такой конфиг не прокатит, т.к. изнутри контейнера приложения хост контейнера с PostgreSQL равен 'postgres'. Чтобы каждый раз не менять файл alembic.ini, был предпринят костыль в файле alembic/env.py , который, если видит что в окружение прокинута переменная "DATABASE_URL" из файла .env в корне проекта (то бишь команда alembic для применения миграций запускается внутри контейнера приложения), то ссылка для подключения к БД чутка меняется в коде запуска alembic'а, хотя скопированный c хоста файл alembic.ini остается с тем же значением 'sqlalchemy.url' которое прописано локально на хосте.</i>
